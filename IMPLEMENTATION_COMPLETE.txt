📋 API ENDPOINT DETAILS
════════════════════════════════════════════════════════════════════════════════

Endpoint: POST /api/chat/send
Route: backend/routes/chat.py

Request Format:
{
  "message": "What is diabetic retinopathy?",
  "conversation_history": [
    {
      "role": "assistant",
      "content": "Hello! I'm here to provide educational information..."
    },
    {
      "role": "user",
      "content": "Previous user message"
    }
  ]
}

Response (Success - 200):
{
  "response": "Diabetic retinopathy is... [response based on knowledge base]"
}

Response (Empty Message - 400):
{
  "detail": "Message cannot be empty"
}

Response (API Key Not Set - 500):
{
  "detail": "Gemini API key not configured. Set GEMINI_API_KEY environment variable."
}

Response (API Timeout - 504):
{
  "detail": "Gemini API request timed out. Please try again."
}

🔄 CONVERSATION FLOW
════════════════════════════════════════════════════════════════════════════════

1. User Opens Chat Widget
   └─> Frontend checks API configuration
   └─> If API key missing: shows warning banner
   └─> If API key valid: ready for chat

2. User Sends Message
   └─> Frontend validates message not empty
   └─> Builds conversation history array
   └─> Sends POST request to /api/chat/send
   └─> Shows typing indicator

3. Backend Processing
   └─> Validates API key is configured
   └─> Loads knowledge base context
   └─> Constructs system prompt with safety guardrails
   └─> Calls Gemini API with full conversation history
   └─> Extracts response from API
   └─> Returns response to frontend

4. Frontend Displays Response
   └─> Adds assistant message to chat
   └─> Shows timestamp
   └─> Animates message slide-in
   └─> Auto-scrolls to new message
   └─> Clears input field

5. User Can Continue
   └─> Chat maintains full history
   └─> Context available for follow-up questions
   └─> Can clear entire conversation with ↻ button
